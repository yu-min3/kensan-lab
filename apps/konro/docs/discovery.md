# Web検索と主要サイト取り込み

一覧の「Webで探す」から料理名・材料を入力し、候補を選んで取り込み画面へ進む。URLから下書きを作り、確認・編集して保存する。有料検索APIや新しいAI APIは追加しない。

## 所有する責務

- `discovery`: 固定サイトの公開検索・タイトル・写真・補足・正規レシピURL。レシピや下書きを保存しない。
- `webpage`: 公開IPへ接続先を固定するHTTP取得。DNS/redirect/port検査、時間・サイズ制限を共有する。
- `importer`: JSON-LD、白ごはんDOM、YouTube概要欄の読み取りとAI結果の検証。`recipe`へ確認保存する。
- `agentclient`: 既存の汎用text jobのみ。runtimeへサイト固有処理は入れない。

## サイト

| サイト | 検索 | 取り込み |
|---|---|---|
| デリッシュ・クラシル | 公開検索の結果領域 | Recipe JSON-LD |
| 白ごはん.com | 公開検索の結果リスト | 材料リスト・説明段落のDOM |
| きょうの料理・味の素・Cookpad・macaroni | 公開検索の結果領域 | Recipe JSON-LD |
| キッコーマン | 公開Web検索RSSを正規URLへ限定 | Recipe JSON-LD |
| YouTube | 公開検索HTMLの動画候補 | 公開動画ページのタイトル・概要欄 |

「主要サイトまとめて」はデリッシュ・クラシル・白ごはん・きょうの料理・YouTube。その他はサイトを選択して検索する。1サイト最大8件、まとめ検索は各サイトを交互に表示する。リンクはホストとレシピURL形の両方を検証し、同じURLはまとめる。

主要ページの実取得と「肉じゃが」での実検索は9サイトで成功（2026-10-17）。全ページの成功を保証するものではない。外部ネットワークに依存する確認は `KONRO_LIVE_TEST=1 go test ./internal/discovery ./internal/importer -run '^TestLive' -v` で明示実行する。通常CIは合成fixtureを使う。

## 制約と失敗時

YouTubeは字幕・音声・映像を取得しない。概要欄に手順がなければAIが推測で補うことは禁止し、元ページや本文貼り付けで補う。AIの結果も材料だけ等の不完全な下書きとして受け入れ、不足を明示する。保存にはタイトル・材料・手順が必要。概要欄の取得に失敗した場合はAI実行を止める。ログイン・CAPTCHA・有料制限は回避しない。

公開HTML・Web検索RSSは安定APIではない。結果領域が変わると0件になる。検索できないサイト・0件を表示し、URLまたは本文からの取り込みを案内する。検索結果以外のおすすめリンクへ自動fallbackしない。

検索HTTPは各2MiBまで、同時取得・解析は全検索を通じて2件、全体20秒。HTML結果のリンクは原則streamで読む。きょうの料理は写真とリンクが別要素のため結果カードのDOMを読む。YouTubeのJSONもデコードする。レシピ取り込みは従来どおり5MiBまで。

## 下書き復元

端末の`konro.import-drafts`にID・元URL・タイトルを保存する。検索から同じURLを選び直したらその下書きを開く。別URLでも過去の下書きは入力画面の一覧から選べる。従来の単独pointerも一覧へ引き継ぐ。保存が完了したIDだけ一覧から除去する。実体は従来どおり`.imports/<id>.json`。

## 検索から直接抽出（2026-10-18）

結果は写真・料理名・出典・取得できた補足をカードに表示する。カードの写真または本文を押すとURL入力を挟まずPOST draftsへ進む。同じURLの未保存下書きは復元する。元ページへのリンクは取り込みと別に置く。

画像は検索HTMLのimg・noscript、きょうの料理のカードから読む。YouTubeは動画ID、デリッシュのlazy画像はレシピIDから公開CDNの標準画像URLを構築する。HTTPSの画像URLだけ返し、ブラウザがreferrerなしでlazy表示する。Konroサーバーは画像を取得・保存しない。写真がない・取得失敗時は「写真なし」とし、候補はそのまま選べる。キッコーマンのRSSなど画像がない検索もある。
