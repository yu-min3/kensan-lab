# レシピと調理状態の境界

レシピを編集しても調理中のチェックが別の手順へ移らないよう、調理セッションは開始時のレシピを保存する。既存ファイルの一括変換は行わない。

| 責務 | 所有するもの | 境界 |
|---|---|---|
| `recipe/codec.go` | YAMLノードと材料・手順・メモの変換 | 未知メタデータ・補足節・画像・出典IDを保持 |
| `recipe/store.go` | 作成・版照合付き更新・ZIP編集保護 | 全入口で同じ基礎検証とatomic書き込み。新規作成は既存ファイルを上書きしない |
| `importer` | 取得・抽出・下書き・AI採否 | 下書きごとに直列化。runtime通信中でも別下書きは操作可能 |
| `agentclient` | 汎用ジョブのHTTP契約 | runtimeのGoパッケージを参照しない。runtimeへレシピ保存先やUI知識を渡さない |
| `useRecipeEditor` / `useImportJob` | 非同期操作・復元・競合・poll | ページは表示と操作の接続を担当 |
| `useRecipeRoute` | レシピURL・履歴・離脱確認 | `#recipe/<id>` / `#new`。再読み込み・戻る・進むに対応 |
| `session.ts` | 開始時のRecipe全文とチェック・タイマー | 調理再開時に最新Recipeを取得しない |

## データ互換性

- YAMLはノードとして読み書きする。編集時の字下げ・引用符は整えるが、未知の値・コメントを残す。編集対象配列の項目に付いたanchorへの外部参照は、失われないよう値へ展開する。
- 材料はbullet、手順は番号付きで1項目1行。`## メモ`から後は見出しも含めてメモ。未知の本文節は保持する。材料・手順節に独自の複数行記法がある場合は、無言で消さず保存を拒否する。
- 手入力とWeb取り込みは`imported/<id>.md`へ保存。ZIPの既存ルートIDは変えず、`konro_edited: true`のレシピを再取り込みで上書きしない。
- 現在の構成は1プロセスがデータディレクトリを所有する。複数replicaからの同時書き込みは対象外。
- 旧調理セッションには開始時の内容がないため、「最新の内容で再開する」を確認してから材料・手順のチェックをリセットする。タイマーと開始時刻は引き継ぐ。
- レシピはURLで開ける。未保存の編集を戻る・進むで破棄する場合は確認する。取り込み画面の下書き復元は既存の下書きIDで行う。

## 検証

`go test -race ./...`、frontend build、`e2e/library.mjs`、別runtime HTTPプロセスを使用する`e2e/import.mjs`で確認する。推論部分のみruntimeのテストfixtureを使用し、実際のsubscription利用枠や料金を消費しない。本番のモデル抽出精度をこの回帰試験で保証するものではない。
